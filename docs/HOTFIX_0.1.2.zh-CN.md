# 0.1.2 箱子占格及提示修复

2026-11-07。用户已实机确认“拾荒者”页签存在，打印耗材1级、2级服务符合预期，双击箱子可得到6卷；3级尚未获用户验收。用户报告箱子和垃圾重叠、第一次开箱有不到一秒的卡顿，要求删除悬浮式提示，仅在描述中提醒预留仓库空间。

## 根因与修复

当前原版GridShapeBuilder(width,height)的构造函数仅设置尺寸并创建全零byte数组。全零表示无占用格，因而原代码虽然宽高3×3，实际九格均为空。此前宿主测试仅检查宽高，未能覆盖真实格子语义，这是实现及验证遗漏。

新建箱子显式调用SetDataFill(3,3)，将九格填为1。onLoaded也补正旧存档中的空占格，同时保留原位置、翻转和旋转，并更新保存过的旧描述。未直接编辑存档文件；已在旧版重叠摆放的物品不会自动重排，请在游戏中拖到空位重新摆放。

物品描述改为：“双击打开，获得6个3D打印耗材。占地3×3格。打开前请确保有足够的仓库空间。”

删除Feedback组件及其创建/销毁和所有Show调用，运行时不再带自制OnGUI悬浮层。柜台不足的原版对话重试仍保留。开箱本身保持所有权、一次执行和失败回滚，空间不足时保留箱子，不显示额外提示。

## 验证及边界

- 新增回归在旧版失败，指出“3×3范围含空占格”；修复后25项宿主回归通过。
- 编译后的生产FilledShape方法与当前游戏真实GridShape.Intersects一起测试：九个位置均与1×1垃圾格碰撞，范围外不碰撞；旧构造方法确实不碰撞。保留位置/旋转/翻转的旧形状修复也通过。
- 检查运行时程序集不再含ScavengerTeams.Feedback类型，生产源码无OnGUI、GUIStyle或Feedback调用。
- 对当前游戏Managed程序集编译通过。物品名称、ID、价格和原始标签不变，服务日程与首次优惠不变。

首次开箱卡顿没有带时间戳的实机性能证据，不能把提示层删除当作已经证明卡顿消失。移除了不必要的GUI首次显示路径，但实际首次开箱延迟仍待用户复测；本轮没有加入额外预热、计时或新的后台流程。
